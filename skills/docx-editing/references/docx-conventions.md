# docx 조판 규율 — 왜 그런지와 직접 짤 때의 함정

`docx_kit`의 기본값이 곧 이 문서다. **모듈을 쓰면 아래를 몰라도 된다.**
여기 있는 이유는 직접 손대야 할 때 같은 자리에서 다시 틀리지 않기 위해서다.

---

## 1. 저널 표 — 세로줄 없음이 기본값이다

출판된 저널 표를 보면 세로줄이 전혀 없고 가로줄도 몇 개 안 된다.

1. **세로줄 금지. 가로줄은 셋만** — top rule / header rule / bottom rule.
   범주 사이 가로줄도 금지다. 변수 내부 범주를 선으로 나누면 오히려 오독을 부른다.
   구분은 **볼드 라벨 + 여백**으로 한다.
   - python-docx에서 `table.style = 'Table Grid'`가 **주범**이다(상하좌우 + insideH +
     insideV를 전부 그린다). 스타일 지정을 빼고 `w:tblBorders`를 직접 주입한다 —
     top/bottom = single, left·right·insideH·insideV = `none`.
     헤더 rule은 마지막 헤더 행 셀의 `w:tcBorders` bottom으로 준다.
   - R의 flextable은 `theme_booktabs()`가 이미 정답이다. **docx 빌더만 예외가 되기 쉽다.**
2. **변수명 = 볼드 그룹 헤더 행, 범주 = 들여쓴 하위 행.**
   라벨 앞의 공백은 Word가 삼키므로 **문단 들여쓰기(`left_indent`)로 변환**한다.
   그룹 헤더는 전 폭 병합해 좁은 열에서 줄바꿈되지 않게 한다.
   - ⚠️ `cell.merge()`는 병합된 셀들의 **빈 문단을 전부 이어붙인다** → 행 높이가 열 수만큼
     폭발한다. 병합 후 `merged.paragraphs[1:]`를 제거할 것.
     **열 폭을 지정한 «다음»에 병합한다** — 병합이 셀 목록을 바꾼다.
   - 그룹 헤더 문단에 `keep_with_next=True` → 라벨만 페이지 끝에 고아로 남지 않는다.
3. **표에 "Panel A/B" 금지.** 그림의 관용이지 표의 관용이 아니다.
   대신 서술형 볼드 소제목 행을 쓴다. 본문 인용도 "Table 3, Panel A" → "Table 3".
4. **회귀표에는 변수마다 `1.00 (ref)` 행을 명시**한다. 라벨에 "(ref: ...)"를 우겨넣지 않는다.
5. **반복되는 그룹 식별자는 열로 반복하지 않고 그룹 헤더 행으로 올린다.**
   코호트/N/사건수/추적기간을 6행에 똑같이 반복하는 것은 스프레드시트지 저널 표가 아니다.
   → `"COHORT (1988-1994): N=12,676; 6,622 deaths; median follow-up 25.5 y"` 한 행으로 올리고
   나머지 열만 데이터로 남긴다. (괄호 중첩을 피하려면 `(...)` 대신 `: ...`)

**제목은 표 «위», 각주는 «아래».** 유의성 별표는 각주에 범례로 한 번만 정의한다.

## 2. 장르를 먼저 정한다

| 장르 | 표 | 왜 |
|---|---|---|
| 저널 투고 원고·전시물 구성안 | `add_journal_table` | 세로줄·색 없음. 저널 관습 |
| 기관 브리프·사례보고서 | `brief_table` | 격자·색 헤더가 **의도된** 디자인 |
| 자유서식 문서 | `render_markdown` | `.md`를 그대로 읽히게 |

「보기 좋으니까」로 고르지 않는다. 원고에 격자 표를 넣으면 관습 위반이고, 브리프에 저널
표를 넣으면 밋밋해지는 게 아니라 **정보가 덜 보인다.**

## 3. 마크다운 → docx 에서 반복되는 결함 넷

`render_markdown`이 전부 처리한다. 직접 짜면 이 넷이 순서대로 나온다.

1. **줄마다 문단을 만든다.** 원본의 하드랩(`\n`)이 문단 구분으로 오해된다 —
   3,800단어가 413문단이 되고 문서 전체가 세로로 늘어진다. **빈 줄만 문단 경계다.**
2. **`**굵게**`가 글자로 남는다.** 별표를 지우고 run 을 나눠야 한다.
3. **빈 문단에 폰트 크기를 준다.** `_para(doc, "", 6)` 은 6pt짜리 **빈 run 을 만든다** —
   보이지 않는 여백이 문서마다 조금씩 다르게 쌓인다. 빈 문단엔 run 을 넣지 않는다.
4. **표를 마크다운 파이프 그대로 문단에 넣는다.** 표 블록은 표로 조립한다.

## 4. 그림

- **그림은 «만든 크기»가 곧 표시 크기다.** docx 안에서 0.85배로 줄이면 글자만 작아진다.
  줄여야 할 만큼 크면 **그림을 다시 만든다.**
- 이미지 원본 비율을 유지한다(가로만 지정하고 세로는 비운다).
- 캡션은 그림 **아래**, 표 제목은 표 **위**. 이 둘은 서로 다르다.

## 5. 만들었으면 렌더해서 «눈으로» 본다

```python
render_docx("out/문서.docx", "scratch/_render")     # 쪽별 PNG
```

구조 검사로 잡히지 않고 **렌더에서만 보이는** 결함이 있다 — 글씨 축소, 원치 않는 쪽 넘김,
칸 밖으로 나간 글자, 별표가 글자로 남은 것, 표 잘림, 빈 페이지.
2026-08-25에 이 단계 하나가 6종을 잡았다.

⚠️ **Word COM 은 `DispatchEx` 로 띄운다.** `Dispatch`(맨몸)는 «이미 떠 있는» 인스턴스에
붙는다. 그 인스턴스가 숨은 채로 멈춰 있으면 렌더가 조용히 죽고, **원인이 파일에 있는 것처럼
보인다.** 그날 나는 「Word가 망가졌다」고 오진했다 — 전에 되던 파일을 열어 보는 판별검사
한 번으로 「파일이 아니라 상태」임이 드러났고 `DispatchEx` 로 즉시 해결됐다.
LibreOffice 대체 경로도 같은 원칙(자기 프로세스를 띄운다)을 따른다.

## 6. 숫자는 타이핑하지 않는다

산출물 수치를 본문에 손으로 적지 않는다. **값 사전 + 자리표시자 + 미치환이면 멈추는 게이트.**

```python
VALUES = {"hr_primary": _ci(row), "n_analytic": _n(row)}   # 산출 파일에서 읽는다
text = text.replace("{{hr_primary}}", VALUES["hr_primary"])
if re.search(r"\{\{[a-z_]+\}\}", text):                     # 남아 있으면 빌드 실패
    sys.exit("치환되지 않은 자리표시자")
```

⚠️ **행을 «고르는» 이름도 숫자다.** 「Model 3」 같은 라벨을 문자열로 박아 두면 모형 구성이
바뀔 때 값은 그대로인 채 **다른 행을 읽는다.** 선택자도 상수 한 곳에서 온다.

## 7. 표가 많은 문서에서 분량이 부는 두 자리 (2026-08-28 실측, 21쪽 → 15쪽)

「길다」는 말을 들으면 문장부터 지우게 되는데, **표가 스무 개쯤 되는 문서에서는 문장이 범인이
아니다.** 아래 둘이 각각 3쪽씩 먹고 있었고, 둘 다 «표의 항목을 하나도 빼지 않고» 회수된다.

**① python-docx 의 `Normal` 기본값은 「문단 뒤 8pt + 줄간격 1.08」이다.**
본문 문단은 보통 빌더가 `space_after` 를 따로 주지만 **표 «셀» 안의 문단은 그 기본값을 그대로
쓴다.** 셀이 500개면 그 여백만으로 몇 쪽이 늘어난다. 문서를 만들 때 한 번 내려 둔다:

```python
nrm = doc.styles['Normal'].paragraph_format
nrm.space_after = Pt(0); nrm.space_before = Pt(0); nrm.line_spacing = 1.0
```

**② 행 높이는 «가장 많이 접힌 열»이 정한다 — 글자 수가 아니라.**
좁은 열 하나에 긴 항목명이 들어가면 그 열이 3줄로 접히고, 다른 칸이 한 줄이어도 **행 전체가
3줄**이 된다. 좁은 두 열을 한 열로 합치면(내용은 그대로 이어 붙여) 접힘이 사라진다.
→ 줄일 곳을 찾을 때는 **글자가 많은 칸이 아니라 «폭 대비 가장 좁은 칸»**을 본다.

⚠ **분량은 혼자 재면 판단이 안 된다.** 「이게 긴가」는 같은 규칙으로 만들어진 다른 산출물과
나란히 놓아야 답이 나온다 — `docx_kit.page_count()` 가 여러 파일을 한 번에 받는 이유다.
그때 **표 칸수를 함께 본다**: 표가 2개인 문서와 20개인 문서는 쪽수를 비교할 사이가 아니다.
(같은 날 실측: 5쪽짜리 «동료 문서» 셋을 21쪽 문서 옆에 놓았는데 그것들은 골격이 다른
옛 서식이었다. 「우리 것이 너무 길다」는 거짓 결론이 그 표에서 나왔다.)
